# PyTunnel

A lightweight ngrok-like tunneling application written in Python. PyTunnel allows you to expose your local development servers to the internet through secure tunnels.

## Features

- **Reverse Proxy Tunneling**: Expose local servers to the internet
- **WebSocket-based Communication**: Efficient bidirectional communication
- **Multiple Client Support**: Server can handle multiple simultaneous tunnels
- **Auto-Reconnect**: Client automatically reconnects if connection is lost
- **Colored Logging**: Beautiful console output with color-coded logs
- **Simple CLI**: Easy-to-use command-line interface

## Architecture

PyTunnel consists of two main components:

1. **Tunnel Server**: Runs on a public server with a static IP address
   - Accepts WebSocket connections from clients
   - Receives HTTP requests from the internet
   - Forwards requests through tunnels to clients

2. **Tunnel Client**: Runs on your local machine
   - Connects to the tunnel server via WebSocket
   - Receives proxied HTTP requests
   - Forwards them to your local service
   - Returns responses back through the tunnel

## Usage

### 1. Start the Tunnel Server

On your public server (with a static IP):

```bash
pytunnel-server --host 0.0.0.0 --port 8080
```

Options:
- `--host`: Host to bind to (default: 0.0.0.0)
- `--port`: Port for HTTP proxy (default: 8080)

The server will start and listen for:
- HTTP requests on the specified port
- WebSocket tunnel connections at `/tunnel` endpoint

### 2. Start the Tunnel Client

On your local machine:

```bash
pytunnel-client 3000 --server http://your-server-ip:8080
```

Arguments:
- `local_port`: The port of your local service (required)

Options:
- `--server`: Tunnel server URL (default: http://localhost:8080)
- `--local-host`: Local host to forward to (default: localhost)
- `--client-id`: Custom client ID (optional, auto-generated by default)

### 3. Access Your Local Service

Once connected, the client will display your tunnel URL:

```
============================================================
  Tunnel URL: http://your-server-ip:8080/abc12345
  Forwarding to: http://localhost:3000
============================================================
```

Now anyone can access your local service at the displayed tunnel URL!

## How It Works

1. **Client Registration**:
   - Client connects to server via WebSocket
   - Client sends registration message with unique ID
   - Server acknowledges and provides tunnel URL

2. **Request Proxying**:
   - HTTP request arrives at server for a tunnel URL
   - Server identifies the client from the URL path
   - Server forwards request through WebSocket to client
   - Client proxies request to local service
   - Client sends response back through WebSocket
   - Server returns response to original requester

3. **Connection Management**:
   - Server tracks active client connections
   - Pending requests are matched with responses via request IDs
   - Auto-reconnect on connection loss
   - Timeout handling for unresponsive requests

## Protocol

PyTunnel uses a simple JSON-based protocol over WebSocket:

### Message Types

- `REGISTER`: Client registration
- `REGISTER_ACK`: Server acknowledgment
- `HTTP_REQUEST`: HTTP request forwarding
- `HTTP_RESPONSE`: HTTP response
- `ERROR`: Error message

### Message Format

```json
{
  "type": "message_type",
  "request_id": "unique_request_id",
  "data": {
    // Message-specific data
  }
}
```

```bash
python -m pytest tests/

# Run with coverage
python -m pytest --cov=pytunnel tests/
```

### Running Locally for Development

Terminal 1 - Start the server:
```bash
python -m pytunnel.server.cli --port 8080
```

Terminal 2 - Start a simple HTTP server:
```bash
python -m http.server 3000
```

Terminal 3 - Start the client:
```bash
python -m pytunnel.client.cli 3000 --server http://localhost:8080
```

Terminal 4 - Test the tunnel:
```bash
curl http://localhost:8080/your-client-id/
```

## Limitations

- **HTTP Only**: Currently only supports HTTP (not HTTPS)
- **No Authentication**: No built-in authentication mechanism
- **Single Server**: No load balancing or high availability
- **Basic Protocol**: Simplified protocol compared to ngrok
